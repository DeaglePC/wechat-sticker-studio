# 微信动态表情工作室

按用户本次请求选择入口。只问方法就回答方法，只要分镜就交分镜。要求做一套时交付能播放的文件。要求上传已有专辑时直接复用现有文件。明确区分本地打包、向微信上传文件、提交审核和安排上架四个结果。

## 做一套

1. 从一句话取出使用关系、角色和口吻，缺少信息时用可逆的创意选择补全，并在交付时说明。没有指定张数时做 16 张。先写对方的上一句话，再定图上的回复和动作。具体配比、母版和生成提示见 [制作手册](references/production.md)。
2. 用当前环境可用的图像生成工具画原创母版，保留文件。以母版为参考试画一张常用回复和一张大动作，对比脸、服装、轮廓和标志物，再展开整套。为每张生成真实不同的关键姿势。模型只负责画面，中文用有授权的字体单独排版。
3. 将透明三格关键姿势交给 `scripts/animate.py`，或用作者提供的序列帧编码。逐张查看起势、峰值和回环，关注容易多画的手、运动中切边的装饰、在深色背景里消失的字。生成封面、图标、横幅、编号文案，以及用于选图的总览。
4. 按 [投稿目录与校验命令](references/package.md) 运行 `scripts/album.py`。交付独立 GIF、预览和通过校验的 ZIP；母版和过程稿另存。报告实际生成的张数和未通过的项目。

所有 `scripts/`、`references/` 路径均相对于本 SKILL.md。通过 `uv run --script` 执行脚本，或在安装了 Pillow 的 Python 3.10+ 环境里执行。生成图像与控制浏览器分别需要宿主提供相应能力。

## 上传到微信

用户要上传、填草稿或送审时，读取 [浏览器投稿手册](references/wechat-upload.md)，运行本地校验，生成本次上传清单，随后**实际打开官方页面并操作**。逐项核对页面回显。按用户授权的目标停在预览、待审核或已预约状态；有明确授权且范围一致时继续执行。账号归属、实名、权属声明或 AI 来源未知时仅向用户询问缺失事实。遇到扫码时把当前页面交给本人，登录完继续同一草稿。仅在用户要了解步骤时，把操作改为说明。

## 验证传播效果

用户要挑选主打图时，给目标用户看几句真实对话，允许他们选“都不会发”。区分愿意试发、隔天再用、收图的人主动要原图这三种信号。用观察到的选择指导下一套；将未试用的创意判断写成假设。
